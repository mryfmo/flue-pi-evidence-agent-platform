# Goal

Add a release validation gate that checks `.orchestration/skills/` for SKILL.md-compatible frontmatter and Hermes-subset boundary violations.

# Scope

- Add `scripts/check-skill-registry.mjs`.
- Add `skill_registry` to `scripts/validate-release.mjs`.
- Document the new gate in `docs/VALIDATION_PLAN.md`.
- Fix only frontmatter conformance issues if the validator finds any.
- Write required P4-T04 artifacts and send AGMSG result.

# Assumptions

- Missing `.orchestration/skills/` must pass with a clear note for container image contexts.
- Schema violations and Hermes runtime markers must fail.
- Rejected and merged registries are skipped for schema conformance, but runtime-marker checks cover all `.orchestration/skills/`.

# Design

- Use a small Node script with stdlib filesystem traversal and simple frontmatter parsing.
- Treat `*.SKILL.md` and `*skill*.md` under `candidates/` and `promoted/` as schema-checked skill files.
- Require promoted skill files to include `version` and `provenance`.

# Tests

- Run the validator on the current tree.
- Run the validator from a temporary cwd without `.orchestration/skills`.
- Run spec-check and validate-release.
