## Normative Markdown extraction

After excluding fenced blocks and an ID heading explicitly suffixed `(non-normative historical inventory)`, support only these syntactic forms:

1. Table row `| <ID> | <Requirement> | ... |`: parse cells, remove exactly one ASCII space immediately inside each syntactic cell delimiter, and compare the remaining Requirement-cell UTF-8 bytes without Unicode, whitespace, punctuation, code-span, or line-ending normalization.
2. Bullet `- <ID>: <Requirement>`: remove the exact `- <ID>: ` prefix and the terminal LF only; compare the remaining UTF-8 bytes without normalization.
3. Heading `## <ID>` followed by its immediately following non-empty single paragraph: remove the heading, intervening blank line, and terminal LF only; compare the paragraph UTF-8 bytes without normalization. Multi-paragraph or ambiguous ownership is fatal.

Every extracted normative occurrence must match exactly one baseline ID and its exact post-revision text. Unsupported forms, duplicate occurrences, normalization-dependent equality, malformed table rows, or text split ambiguously across blocks are fatal.

- The accepted A0 decisions and pre-A2 JSON entries are the more complete machine-consumed contract for the 13 semantically compatible pairs. Aligning their Markdown projections removes duplication without choosing new behavior.

- FR-001 is not a wording-only divergence: its existing meaning violates the accepted trust boundary and must be corrected explicitly.
