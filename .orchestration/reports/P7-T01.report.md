# P7-T01 Report

## Summary

Implemented a native Hermes Skill Subset lifecycle flow without introducing Hermes runtime, LLM calls, or new dependencies.

## Changed Files

- `scripts/skill-lifecycle.mjs`
  - Adds `observe`, `decide`, and `apply` subcommands.
  - `observe` collects task evidence from reports, validation, and acceptance files, calls the existing `scripts/data_guard.py redact_text` path, and writes an AutoSkill-compatible manifest and redacted dataset.
  - `decide` performs deterministic registry overlap scoring across candidates and promoted skills, then writes a lifecycle run log with `promotion_allowed=false`.
  - `apply` records the caller-selected decision, creates a candidate only for `create`, and appends a triage record while leaving final authority with the orchestrator.
- `scripts/skill-activate.mjs`
  - Adds progressive disclosure over promoted skills: ranked name/description output for a query, and full body output with `--full`.
- `tests/unit/skill_lifecycle.test.mjs`
  - Adds fixture-based `node:test` coverage for observe/decide/apply and activation loading.
- `package.json`
  - Adds `skill:lifecycle`, `skill:activate`, and `test:skill-lifecycle` scripts.
- `.orchestration/skills/TRIAGE.md`
  - Documents how native lifecycle automation feeds triage without promotion authority.
- `.orchestration/autoskill/config/ADOPTION_PLAN.md`
  - Adds a P7-T01 cross-reference and states this native lifecycle does not replace AutoSkill dry-run generation.

## Acceptance Evidence

- Focused tests pass: `npm run test:skill-lifecycle`.
- Real-evidence demo pass: copied P2-T07b report, validation, acceptance, registry skills, and `data_guard.py` into a temporary fixture; ran `observe -> decide -> apply --decision create`; verified manifest, lifecycle run log, candidate, triage row, and `promotion_allowed=false`.
- Release gate pass: `npm run validate-release` returned `validate-release:passed`.
- Network/LLM/Hermes check: grep found no network client or Hermes runtime invocation in the new scripts. Matches are limited to `data_guard.py` child-process invocation, offline AutoSkill dataset field names, tests invoking Node scripts, and documentation references.
