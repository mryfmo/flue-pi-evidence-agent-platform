# A0-01 Report

## Summary

Implemented routing fail-closed controls for trusted classification and explicit catalog route authorization.

Policy now trusts `input.decision.classification.value` only when accompanied by `input.decision.classification.trust_proof` matching the catalog-declared producer `flue-pi-data-guard`, verifier `flue-pi-platform-gateway`, and evidence kind `presidio-sqlglot-redaction-v1`. Caller-origin `data_classification` is not trusted when the catalog declares classification metadata.

## Known Limitations

- Product runtime was not edited by task constraint. Existing runtime construction does not yet populate `decision.classification`, so production calls using the new catalog shape fail closed until a later runtime WU adds the trusted classification producer/proof.
- `policy/routing_test.rego` is outside the allowed edit list but still runs in `opa test policy`; it builds a pre-A0-01 minimal catalog. `policy/routing.rego` keeps a narrow compatibility path only when `input.policy.classification` is absent so that existing out-of-scope tests continue to pass. The production catalog and schema require classification metadata.

## Residual Risks

- The trust proof is a policy-input proof contract, not cryptographic verification inside Rego. The platform gateway must construct OPA input from verified classifier output and must not pass caller body proof fields through as trusted data.
