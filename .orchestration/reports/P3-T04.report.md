# P3-T04 Report

## Summary
Implemented AST-based SQL validation for metric queries in `scripts/data_guard.py`. The validator now accepts aggregate-only SELECT queries over allowlisted tables while denying broad projection, non-grouped bare columns, PII columns in any clause, set operations, unknown tables, mutations, and multi-statement SQL.

No TypeScript files were changed. The existing named metric query and result shape remain compatible, with additional evidence booleans for the new rejection classes.

## Changes
- Added `ALLOWED_TABLES` and `ALLOWED_AGGREGATES` constants.
- Added `validate_metric_sql` and `validate_select_projection` SQLGlot AST helpers.
- Extended `GuardResult` with:
  - `rejectedNonAggregateProjectionSql`
  - `rejectedSelectStarSql`
  - `rejectedTableNotAllowlistedSql`
- Added acceptance and rejection coverage in `tests_py/test_data_guard.py`.
- Documented SQL validation rules in `docs/DATA_GOVERNANCE.md`.

## Rule-to-Test Mapping
| Rule | Test coverage |
| --- | --- |
| Exactly one SELECT statement; DML/DDL/engine control denied | `test_reject_unsafe_sql`; existing parser/mutation/multi-statement examples |
| No UNION/INTERSECT/EXCEPT | `test_rejects_non_aggregate_or_out_of_policy_sql` union case |
| Projection is COUNT/SUM/AVG/MIN/MAX or grouped plain column | `test_accepts_safe_aggregate_sql_and_parser_failure`; bare projection rejection |
| `SELECT *` denied | `test_rejects_non_aggregate_or_out_of_policy_sql` star case; `rejectedSelectStarSql` evidence assert |
| FROM tables allowlisted | unknown `invoices` rejection; `rejectedTableNotAllowlistedSql` evidence assert |
| PII columns denied in every clause and subquery | WHERE, nested subquery, and HAVING PII rejection cases |
| Existing metric workflow unchanged | `test_metric_query_redacts_pii_and_rejects_unsafe_classes`; full `npm run validate-release` pass after sandbox escalation |
