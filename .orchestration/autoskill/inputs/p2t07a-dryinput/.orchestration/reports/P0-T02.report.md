## Failure Classification

All observed failures are environmental or packaging/tooling reproducibility issues:

- `opa`: missing/incompatible OPA binary on darwin/arm64.
- `vitest_all`: OPA fail-closed plus sandbox-denied localhost bind.
- `npm_audit_prod`: intentionally not assessed because network is forbidden.
- `npm_sbom_prod`: host npm command does not provide usable `sbom` output.

No product defect was identified by this measurement.

## Recommendations for G4/G11/G15

- G4: add a CI matrix or preflight that separates product failures from platform prerequisites: OPA binary availability, localhost bind permission, npm SBOM support, and audit network availability.
- G11: pin or bundle the npm/SBOM producer used by the release gate so `npm_sbom_prod` cannot silently depend on host npm capabilities.
- G15: document sandbox requirements for loopback server tests, or split tests that require `127.0.0.1` binding from sandbox-compatible unit/component gates.
- P2-T01/P2-T03 input: make OPA binary selection explicit for darwin/arm64, likely via `EAP_OPA_BINARY` or platform-specific package resolution.
