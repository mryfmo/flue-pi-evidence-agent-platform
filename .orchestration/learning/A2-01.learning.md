# A2-01 learning

Evidence path syntax and file existence are not evidence authenticity. Post-run traceability must reuse the release verifier so report order, source cleanliness, run identity, gate-manifest identity, record status, return code, and exact stdout/stderr/artifact bytes form one provenance chain. Empty streams are valid only when their empty-byte digest is part of that chain.

Catalog structure and post-run evidence must be separate modes. Requiring final evidence during the early `spec_traceability` gate creates a validation cycle because the full run has not yet produced its report and records. Structural modes should validate exact path/gate mappings without physical evidence; only the explicit post-run mode should dereference the canonical A1 evidence set.

Syntax-aware requirement extraction must fail closed at block starts, but its candidate grammar must remain narrow. Treating any heading that merely begins with an ID as a requirement would misclassify descriptive headings such as `SPEC-20 normative capability requirements`; exact supported forms and explicitly enumerated unsupported forms avoid both bypass and overmatching.
