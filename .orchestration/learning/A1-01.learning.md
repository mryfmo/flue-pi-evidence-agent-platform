# A1-01 learning triage

## Candidate

Release evidence must hash all intended source bytes while excluding mutable validation outputs from the source set and binding those outputs separately. A single command manifest must be both executable by the producer and compared exactly by the consumer; matching display names or a count is insufficient.

Recursive entry sorting is not equivalent to sorting the flattened relative-path set; a directory and sibling file with the same prefix expose the difference. Repository identity parsers must anchor the complete transport and host, not search for a trusted-domain substring.

## Disposition

Candidate only. It is reflected in the A1-01 implementation and tests but is not promoted to a reusable project learn or skill by this worker. Orchestrator acceptance and future clean-tree release execution are required before promotion.

Stage 2A confirmed the generated inventory can be structurally valid while its source identity is still dirty. Manifest correctness and release-evidence acceptability are separate checkpoints: the former may pass before the orchestrator establishes the audited clean source state required by the latter.

Post-checkpoint line-ending normalization is a source-byte mutation even when semantics are unchanged. The release manifest must always be generated after such normalization; an otherwise valid pre-normalization manifest correctly fails its byte-digest binding.

An upstream merge that adds non-code release files changes the deterministic source tree just like code changes. The release inventory must be regenerated after merge and must bind binary bytes directly; filename presence alone is insufficient.

A complete source identity must include every byte that can alter a release gate's result, even if that byte lives under a normally excluded plan/evidence directory. If executable validation reads a frozen revision contract or baseline, those exact files must either be release-bound inputs or moved into an already bound source location.

An exact-file whitelist inside an excluded directory must also permit only the ancestor directories required for recursive traversal. Reusing the same path predicate for discovery and Git/index/worktree comparison prevents manifest and dirty-state scope from diverging.

Discovery alone cannot enforce mandatory inputs because an absent file disappears from enumeration. Required release sources must be merged into the final candidate set before stat/read so regeneration cannot bless deletion. Directory ancestors also need explicit traversal coverage; a descendant inclusion rule is inert if its parent directory is filtered first.

A clean source identity does not imply release-gate success: deterministic format conformance must be checked before claiming evidence readiness. When a committed formatter failure spans WU ownership, stop at the first gate and require a new checkpoint after the scoped correction instead of mutating the source during evidence production.

Portable timeout enforcement needs a one-way deadline latch and process-group ownership, not merely a timer around a leader process. Once timeout wins, leader close must not cancel the grace-phase group kill; otherwise descendants survive while the wrapper reports completion. Exact tuple matching also prevents an outer watchdog from preempting the authoritative timeout result.

Process-group ownership must also cover termination of the wrapper itself. A synchronous parent's maxBuffer watchdog signals the wrapper, not its detached child group, so SIGTERM/SIGINT handlers must enter the same first-latch cleanup path as the deadline. Process tests that can create detached groups must handshake the PGID and retain an unconditional group-kill fallback in `finally`, including the test intended to detect the orphan bug.

A wrapper cannot rely on `process.exitCode` for bounded fatal settlement while a live child or inherited capture descriptor still owns event-loop handles. If the final process-group kill fails, explicitly close pipe forwarding and exit with the internal-error code after the mandatory grace attempt. Pipe-and-forward also needs benign `EPIPE` handling because a synchronous parent may close its capture pipe when `maxBuffer` is exceeded; that closure must not preempt the wrapper's signal-cleanup latch. Fault-injection tests should prove both the bounded wrapper exit and the fixture's deliberate cleanup of the child that the injected failure leaves alive.
