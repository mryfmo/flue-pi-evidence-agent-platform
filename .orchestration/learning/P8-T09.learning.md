# P8-T09 Learning

## What Changed Decision-Making

- Container-only ENOENT from tests can be the runtime image contract, not a test problem. Here `sqlite3` is required by both platform-health and DB fixture tests, so the lazy fix is one Dockerfile package.
- Bash guard path extraction must treat redirect/control separators as token boundaries. Otherwise `>policy/file` and `<policy/file` evade the same checks as space-separated paths.
- A guard carveout should happen at extraction only when the whole command is the approved orchestration operation. If the command is chained or redirected, extract normally and let existing deny policy fire.
- LiteLLM custom callbacks must be referenced as `module.instance`; a bare callback name is not enough for module resolution.

## Where To Apply

- Future container CI failures should distinguish missing image tools from missing host tools before changing tests.
- Future pretool guard fixes should add a positive allow test and adjacent negative tests for each carveout.
- Future LiteLLM config changes should keep callback implementation, callback reference, static config validation, and metadata-only tests in the same change.
