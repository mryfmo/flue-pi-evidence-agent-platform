# P9-T01 Learning Triage

## Reusable candidates

1. **Adapter existence is not production-path evidence.** A production adapter and green contract test do not prove readiness unless caller reachability shows the real workflow selects it and an integration test traverses the full path. Apply to future architecture audits and release acceptance.
2. **Release evidence must bind source and gate identity.** A passing report without revision/tree and gate-manifest digest is stale evidence, not current evidence. Apply to validation reports and ops preflight.
3. **Specification gates must validate the complete normative ID set.** File existence and minimum line counts detect missing files, not semantic coverage. Apply to `spec-check` and traceability design.
4. **Remote executor boundaries must own every filesystem operation.** Passing a remote handle ID into host-path helpers defeats the abstraction. Apply to sandbox designs and integration tests.
5. **A policy fallback is a security decision, not error handling.** OPA evaluation failure must deny explicitly; silently changing authority to a heuristic is fail-open even when the heuristic covers common cases.
6. **Negative network tests need a positive control.** An arbitrary non-zero connection exit cannot prove egress enforcement; use a controlled reachable endpoint and paired allow/deny assertions.

## Triage decision

- reusable: yes
- validated against current code/evidence: yes
- promotion or policy change: **not performed**; orchestrator decision required
- recommended reflection targets: future production-readiness audit checklist, release evidence schema, sandbox integration test plan
