# P2-T07b Learning

## Learned
- Current `codex exec` uses `--output-last-message <FILE>` for final output.
- Passing prompt content via stdin avoids placing prompt text in process arguments.
- Docker can receive secret values with `-e NAME` while the host command supplies the env value, avoiding literal token values in runtime arguments.
- Pinned AutoSkill commit `94c47ca4` exposes the usable offline conversation CLI as `python -m autoskill.offline.conversation.extract`; the root `python -m autoskill offline` router is not wired to provider flags.
- The offline conversation loader expects OpenAI-style JSON/JSONL records containing `messages`.
- The same pinned commit imports `autoskill.offline.conversation.utils.ban_mock` but does not ship the `utils` package, so image builds need a local fail-closed guard shim until upstream is fixed or the pin moves.

## Applied
- `codex_auth_proxy.mjs` uses stdin for the prompt and reads the final assistant message from the output file.
- `run_autoskill.sh` passes `OPENAI_BASE_URL` and `OPENAI_API_KEY` by env name only.
- `build_inputs.py` now writes `openai_conversations.jsonl` for the offline CLI, and `run_autoskill.sh` passes that file to the module CLI.
- `Dockerfile.autoskill` creates the missing `utils` package before installing the pinned checkout.
