# P2-T06a Learning

## Summary

OpenSandbox is now treated as a product-required remediation isolation layer, not merely an orchestration convenience. Local release validation remains deterministic through the existing local workspace behavior.

## Learnings

- The current code path copies workspaces and runs pytest on the host, so it lacks kernel, process, and network isolation.
- The clean integration boundary is a `SandboxExecutor` contract with `LocalWorkspaceExecutor` and `OpenSandboxExecutor`.
- `EAP_SANDBOX_RUNTIME=opensandbox` must fail closed if OpenSandbox is unreachable; local fallback must be an explicit operator config change.
- OpenSandbox verification is CI-only on ubuntu because macOS Apple container does not expose the Docker API required by OpenSandbox local runtime.

## Plan Updates

T06b should extract the local executor behind the contract without behavior changes. T06c should pin OpenSandbox artifacts, add `eap.sandbox`, and add the CI-only integration job.
