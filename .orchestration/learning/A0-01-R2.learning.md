# A0-01-R2 Learning Triage

## Learning

Existential checks over separate catalog rows do not prove tuple integrity when an identifier is duplicated. Bind every authorization field to one row for the allow decision; retain independent checks only for diagnostic deny reasons.

Constant provenance fields describe an expected producer path but cannot authenticate caller-controlled input. The actual security precondition is gateway/PEP ownership and isolation of the OPA input document.

## Validation

The split-witness fixture independently satisfies the route-id/provider/model/classification field checks across three rows but has no complete matching row. Direct OPA evaluation denies with `route_tuple_mismatch`, and the full suite passes 41/41.

## Disposition

Reusable and validated, but not promoted by this worker. The orchestrator may consider the tuple-binding rule as a future policy-review candidate.
