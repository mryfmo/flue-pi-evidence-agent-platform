# Task P3-T01: Externalize tenant authorization to an OPA data document (G6)

## 1. Role

You are Codex CLI, model gpt-5.5, reasoning effort high, standing agmsg worker codex-gpt55-high. Worker, not orchestrator. Perform only this task.

## 2. Objective

Remove the hard-coded `"acme"` tenant from all Rego policies and replace it with a versioned OPA data document, preserving current behavior (acme allowed) and fail-closed semantics. Extend tenant boundary tests.

## 3. Defensive engineering scope

Authorization hardening. No offensive content.

## 4. Background / fixed decisions

- Current hardcodes: policy/agent.rego (`input.tenant != "acme"` deny + allow condition), policy/routing.rego (same), policy/sandbox.rego (same).
- **Decision 1 — single source**: new data document `policy/tenants.json`:
  ```json
  { "eap": { "tenants": { "allowed": ["acme"] } } }
  ```
  All three packages consult `data.eap.tenants.allowed` (set membership). Tenant NOT in the list → deny. **Empty or missing list → deny everything (fail closed)** — verify OPA v0 semantics make absent data falsy in the allow rule; write it so that is guaranteed.
- **Decision 2 — adapter**: `src/lib/opa.ts` `evaluatePolicy` gains the data document: pass `--data policy/tenants.json` in addition to the policy file (backward-compatible signature; a caller-supplied override path is fine but default to policy/tenants.json).
- **Decision 3 — scope**: policy externalization + tests only. No tenant provisioning API, no per-tenant config plumbing elsewhere, no OPA bundle server (that is P3-T02).
- Behavior preservation: all existing tests (which use acme) must stay green; full suite 20/20.
