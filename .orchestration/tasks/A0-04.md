## 5. Mandatory contract

One issue closes only when the same issue-scoped record proves all of:

1. The identified defect is removed with issue-specific proof.
2. Every required regression check is present and passed.
3. The rescan is clean for that issue; a clean global scan alone is insufficient.
4. Every hypothesis is verified using its own evidence.
5. Required impact evidence is complete and passed.
6. Every patchable hypothesis has at least two distinct candidate IDs associated with that hypothesis.

Do not count candidates across hypotheses, allow duplicate IDs to reach two, combine witnesses from different issues, or define competing prose predicates. All normative documents must reference the same schema and `data.eap.closure.remediation_success`/`closed` contract with a machine-checked digest or equivalent exact binding.

## 6. Adversarial acceptance

- Clean rescan without issue-specific defect-removal proof => open.
- Evidence belonging to a different issue => open.
- Missing or failed required regression check => open.
- Remaining issue-scoped rescan finding => open.
- Missing/failed impact evidence => open.
- One patchable hypothesis with only one distinct candidate => open.
- Two duplicate candidate records with one ID => open.
- Two candidates spread across two hypotheses, leaving one below two => open.
- Missing or unverified hypothesis evidence => open.
- One complete, internally consistent record => closed.
- Missing, malformed, unknown, or wrong-typed trust-boundary fields => fail closed.
