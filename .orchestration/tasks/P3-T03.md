Upgrade the data guard's PII detection from the current minimal custom regex recognizers to Presidio's built-in pattern/checksum-based recognizers, adding entity coverage and precision regression tests — while staying fully offline and deterministic (no NLP model downloads).

## 4. Background / fixed decisions

- Current: scripts/data_guard.py uses custom regex `PatternRecognizer`s for deterministic examples only.
- **Decision 1 — no model downloads**: NLP-model NER (spaCy en*core_web*\*) is explicitly deferred; record adoption criteria in the report (when recall on free-text fields becomes a requirement). Everything added must run offline.
- **Decision 2 — use Presidio built-ins that are pattern/checksum based**: add EMAIL_ADDRESS, PHONE_NUMBER (the `phonenumbers` library is already installed as a Presidio dependency — validation-based, not just regex), CREDIT_CARD (Luhn checksum — test that a Luhn-invalid 16-digit number is NOT flagged), IP_ADDRESS, and URL if available offline. Keep existing custom recognizers if they add coverage.
- **Decision 3 — extend enforcement surfaces consistently**: `analyze`/anonymize path, `redact_text` command, and the PII-column projection rejection in SQL validation (add the new entity-related column names where sensible, e.g. phone/credit_card columns).
- Precision tests (tests_py): per entity type at least one true positive AND one guarded true negative (e.g. 16-digit order number failing Luhn; version strings not IPs). Coverage stays >= 85%.
- Behavior compatibility: existing tests and the E2E data evidence shape must stay green (22/22 gates).
- `.agents/worklog/**` allowed for your process records.
