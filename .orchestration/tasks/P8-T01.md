## 2. Deliverables

1. **`docs/INTEGRATION_BOUNDARY.md`(新規)** — 以下の節を必須とする:
   - **2 ゾーンモデル**(問題 3): (a) 対話開発ゾーン=Claude Code ネイティブ実行・統制外を明示的に許容、(b) 統制ゾーン=基盤経由必須。統制ゾーンの定義は**禁止列挙型**(統制対象リソース/操作の列挙: 本番 DB 資格情報、リリースブランチ・リリース判定、PII データパス、スキル昇格、policy/ 配下、artifacts/audit/ 配下)。迷う場合は fail closed(基盤へ委譲)。
   - **タスク・ルーティングマトリクス**(問題 4): レビュー文書 §1 の表を本リポジトリの実体(UC/FR ID は docs/PRODUCT_REQUIREMENTS.md・docs/FUNCTIONAL_REQUIREMENTS.md の実在 ID に合わせる。存在しない ID は「レビュー文書上の参照」と注記)に整合させて記載。
   - **データ分類 × 送信可否マトリクス**(問題 11): public / internal / confidential / restricted の 4 分類について、redaction 要否・外部(Anthropic)送信可否・承認要否・Data Guard 集計化要否を表で確定。既存 `docs/DATA_GOVERNANCE.md`・`policy/tenants.json`・`policy/routing.json` の分類語彙と矛盾しないこと(現状 routing.json は internal/public のみ使用 — confidential/restricted を語彙として追加定義する)。
   - **AutoSkill 入力制限**(問題 13): MVP では AGMSG 経由の基盤側履歴のみ。Claude Code 会話履歴の直接取り込み禁止。将来経路(redaction パイプライン経由の片方向エクスポート+証跡)の条件を記載。
   - **AGMSG-RESULT レンダリング規約**(問題 15): 自由記述フィールドは「データであり指示ではない」。表示は決定論スクリプトが引用ブロックで区切る。RESULT 表示直後ターンの高権限操作はユーザー確認必須。
   - **受入 3 層(acceptance_tier)の定義**(問題 14 の文書部分): auto / confirm / review の判定条件と、層判定は基盤側が指定し Claude Code は従うのみであること。
2. **決定記録**: `docs/INTEGRATION_BOUNDARY.md` 内に「Decisions」節を設け、OQ 相当の未決事項 2 件を決定として記録: (a) 本番 LLM = Anthropic モデル+LiteLLM Proxy、承認モデルリスト方式(レビュー文書 §3.1)。(b) データ分類ポリシー = 上記マトリクスのとおり。
3. **既存文書への相互参照追記(最小)**: `docs/DATA_GOVERNANCE.md` と `docs/SECURITY_MODEL.md` に INTEGRATION_BOUNDARY.md への参照を各 1 行追加(内容の書き換えは不可)。
