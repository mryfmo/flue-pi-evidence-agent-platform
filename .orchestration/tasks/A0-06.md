## 5. Mandatory contract

1. Define one canonical acceptance-tier schema and one closed, machine-verifiable risk-input/predicate contract. Normative documents reference the schema; they must not copy formulas that can drift.
2. Auto acceptance is allowed only for the exact low-risk predicate. Missing, unknown, malformed, or contradictory risk inputs fail closed to review.
3. Define versioned HTTP endpoints for supported operations with request/response schemas, all success and negative status codes, and one closed error envelope. Every OpenAPI `$ref` must resolve.
4. Persist a pending approval record before returning `needs_review`. Bind tenant, task/run, source revision/digest, evidence digest, action, requester identity, expiry, decision, approver identity, and resume state.
5. Approve/reject/expire/resume are closed state transitions. Approval requires an authenticated authorized approver from the same tenant; source/evidence must still match; expiry is enforced; resume is exactly-once and idempotent.
6. Manual file edits, caller-supplied identity/provenance strings, stale approvals, and duplicate resume never authorize.

## 6. Adversarial acceptance

- Anonymous, unverified, wrong audience/issuer, unknown role, insufficient role, foreign-tenant approver => deny.
- Missing/unknown/malformed acceptance tier or any risk input => no auto acceptance.
- Expired approval, approval before pending persistence, stale source revision/digest, changed evidence digest, action mismatch, task/run mismatch => deny resume.
- Pending, rejected, expired, or already-resumed state => deny resume with a non-empty closed reason.
- Duplicate approve/reject/resume requests with the same idempotency key produce the same terminal representation; a different payload under a reused key is conflict.
- OpenAPI covers validation/authn/authz/not-found/conflict/expired/rate-limit/internal failures and never returns a success schema for them.
- A complete low-risk record validates and auto-accepts; a complete approved, unexpired, source-bound record resumes exactly once.
