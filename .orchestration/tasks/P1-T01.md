## 7. Fixed design decisions (render these; flag conflicts as open questions, do not silently change them)

1. **Coexistence, not replacement**: `src/lib/localGateway.ts` stays untouched as the deterministic validation provider. `validate-release` keeps using it exclusively (no external nondeterminism in gates). The production gateway is an additional Pi provider registration behind the same `openai-completions` contract.
2. **Policy-driven routing, no learned router**: routing decision = pure function of {tenant, data_classification, task_kind, cost_budget, latency_target} → {provider, model_id, fallback_chain}. Policy lives in a versioned config (JSON/YAML) and is authorized through OPA (new Rego package `eap.routing`, same fail-closed adapter pattern as `src/lib/opa.ts`). Learned/semantic routers are explicitly out of scope (recorded decision, revisit only with new requirements).
3. **Security invariants** (each must appear as a numbered invariant with its enforcement point):
   - Outbound prompt redaction hook before any external call (reuse the Presidio/data_guard recognizer patterns; offline, deterministic).
   - Audit ID + OpenTelemetry trace ID propagated on every call and recorded in the audit JSONL (reuse src/lib/audit.ts) together with provider, model_id, request/response content digests (hashes, not raw content), token counts, latency, and routing decision.
   - Fail closed: routing policy unavailable, redaction unavailable, or OPA deny → no external call.
   - API keys via environment injection only (secret-manager integration is G3/P2-T05); keys never logged, never in agmsg messages, never in audit records.
4. **Provider candidates** (configurable model IDs, no hard-coding in code): Anthropic API (default `claude-sonnet-5`, low-cost `claude-haiku-4-5-20251001`), OpenAI API (`gpt-5.5`), and self-hosted OpenAI-compatible endpoints (e.g. vLLM). Fallback chain example: primary → secondary provider → deterministic local gateway (degraded, summarization marked as deterministic-fallback in audit).
5. **Testing/gating**: CI uses contract tests against a mock provider (extend the localGateway harness) — new release gate "llm_contract" (name final at P1-T03). Live-provider smoke is a manual/ops runbook action, never a release gate.
6. **G12 measurement**: every gateway call emits a telemetry span (existing JSONL exporter) with latency_ms, input_tokens, output_tokens, estimated_cost; aggregation deferred to Phase 5.
7. **Migration plan section**: P1-T03 minimal implementation scope = one provider (env-key), redaction hook, audit/trace propagation, routing config with 2 entries, contract test. Everything else marked later-phase.
