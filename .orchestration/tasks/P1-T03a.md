## 7. Implementation instructions

1. `policy/routing.json`: follow the design doc example — version, defaults.fallback_chain, 2 routes (`acme-internal-summary-fast` → anthropic/claude-sonnet-5; `acme-public-summary-low-cost` → anthropic/claude-haiku-4-5-20251001), providers map with `api_key_env` names only (never secret values).
2. `policy/routing.rego` (package `eap.routing`, v0 syntax like agent.rego): deny when tenant mismatch ("acme" for now, consistent with agent.rego), deny unknown route id, deny when input.data_classification == "restricted" and provider type is external (only `local_gateway` allowed for restricted), default allow = false, allow only for known route + tenant match + classification permitted.
3. `src/lib/router.ts`: strict types for RoutingInput/RouteDecision mirroring the design contract; `selectRoute(input, policyDoc)` = pure function (exact match on the 5 fields; fall back to defaults.fallback_chain when no route matches → decision marked `route_id: "default"`); `authorizeRoute(...)` calling the OPA adapter with package `eap.routing`, fail-closed (any error → not allowed).
4. `src/lib/opa.ts`: add optional package-path parameter with default preserving current behavior; do not change existing call sites.
5. `tests/component/routing.test.ts`: pure-function tests (match, no-match→default, deterministic output) + OPA tests via the adapter (allow for valid acme route, deny for tenant mismatch, deny restricted+external, fail-closed when EAP_OPA_BINARY points to a nonexistent binary). Follow the style of tests/component/opa.test.ts.
