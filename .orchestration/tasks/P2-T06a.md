## 7. Fixed design decisions (render faithfully)

1. **Coexistence, not replacement** (same pattern as the production gateway): a typed `SandboxExecutor` contract with two implementations — `LocalWorkspaceExecutor` (current code.ts behavior; remains the validate-release path so gates stay deterministic and runnable everywhere) and `OpenSandboxExecutor` (product path). Runtime selection via config/env `EAP_SANDBOX_RUNTIME=local|opensandbox`; default `local`.
2. **Typed contract** (design-level TypeScript signatures): `create(spec) -> SandboxHandle` (spec: image/tag pinned, cpu/mem limits, timeout, network policy); `putFiles(handle, files)`; `exec(handle, argv, {timeoutMs}) -> {exitCode, stdout, stderr}`; `collectArtifacts(handle, paths, {maxBytes}) -> files`; `destroy(handle)`. All operations carry audit_id/trace_id.
3. **Security invariants** (numbered table: invariant → enforcement point → test idea):
   - No credentials or host env leakage into sandboxes (explicit allowlist of injected variables, default empty).
   - Network egress denied by default per sandbox; any allow requires a per-run policy entry evaluated via OPA (new Rego package `eap.sandbox`, fail-closed, same adapter).
   - Artifact-only retrieval with size caps; no host filesystem mounts of secrets or repo-external paths.
   - Sandbox lifecycle audit events (create/exec/collect/destroy with digests, image tag, limits) via src/lib/audit.ts.
   - **Fail closed, no silent fallback**: if `EAP_SANDBOX_RUNTIME=opensandbox` and the server is unreachable, remediation runs must fail — never silently degrade to local execution (degradation is an explicit operator config change).
4. **Version pinning**: OpenSandbox npm SDK pinned exact (worker of T06c verifies and pins); server image pinned by tag+digest; sandbox base image pinned by tag+digest. All recorded in config, never `latest`.
5. **Verification strategy**: local validate-release keeps using LocalWorkspaceExecutor (all 20 gates unchanged). NEW CI-only job `opensandbox-integration` (ubuntu, docker): start pinned opensandbox-server, run contract tests (create/exec/collect/destroy + egress-deny + credential-isolation assertions), upload evidence. Record explicitly that this gate is CI-only because macOS lacks a Docker API runtime.
6. **Migration plan**: T06b = extract SandboxExecutor interface + LocalWorkspaceExecutor refactor of code.ts (behavior-preserving, all gates green) + contract tests; T06c = OpenSandboxExecutor via npm SDK + eap.sandbox policy + CI integration job. Kubernetes runtime and stronger runtimes (gVisor etc.) = later phase, listed out-of-scope.
7. **Traceability proposals** (do not edit existing files): REQ-SANDBOX-001 (product isolation layer), REQ-SANDBOX-002 (fail-closed, no silent fallback), REQ-SANDBOX-003 (credential isolation + egress deny by default), REQ-SANDBOX-004 (lifecycle audit).
