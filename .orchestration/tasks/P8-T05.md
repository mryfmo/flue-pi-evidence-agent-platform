# P8-T05: 障害時 fail-closed 連鎖の検証(LiteLLM 停止・agmsg 失敗・状態不明)

- Author: orchestrator-fable5, 2026-07-08
- Basis: `.orchestration/analysis/litellm_claude_code_integration_review.md` 問題 16。前提: P8-T03(llm_unavailable)、P8-T04(status.mjs / delegate.mjs / platform-health.mjs)accepted。

## 1. Objective

新たに増えた障害点(LiteLLM Proxy 停止、Anthropic 不達、agmsg 書込失敗、RESULT 未着)それぞれの「止まり方」が fail-closed であることをテストで固定する。「タイムアウト後の成功扱い」「無限待ち」「Claude Code の勝手な代行」の 3 失敗モードが起きないことを証明する。実ネットワーク・実 LLM 不使用(localhost の接続拒否・ハング・スタブのみ)。

## 2. Deliverables

1. **`tests/failure/llm_outage.test.ts`(新規)** — 既存 tests/failure/ の流儀に従い:
   - PI_PROVIDER=prod + LITELLM_BASE_URL が接続拒否(未使用 localhost ポート)→ `ok:false, reason=llm_unavailable`。成功応答・deterministic-fallback 成功が返らないこと。
   - 応答が 2 秒タイムアウトを超える(ハングするローカルスタブ)→ 同様に `llm_unavailable`。監査ログに成功イベント(llm_gateway_call)が**記録されない**こと。
   - fallback チェーン全滅時に routing_decision が結果に含まれ、失敗理由が機械可読であること(回帰)。
2. **agmsg 書込失敗テスト** — `scripts/orchestrator/delegate.mjs` に対し、読取専用/存在しないディレクトリの agmsg DB を指定した場合に非ゼロ exit +「task not delegated」相当の機械可読エラーで終わり、リース・イベント台帳に**部分書き込みが残らない**こと(受理曖昧の禁止)。テストは一時ディレクトリで実施。
3. **状態不明テスト(補強)** — status.mjs: RESULT 未着 task_id で `state: unknown` になること、および出力に代行実行を示唆する文言が含まれないことを既存 P8-T04 テストが未カバーの範囲で補強(重複するなら追加不要と報告に明記)。
4. **platform-health の障害検知テスト** — litellm config 破損(違反 config への一時差し替え)で fail、agmsg DB 不達で fail、いずれも exit 1。--live なし既定で外部疎通が skip 表示になること。
5. **`docs/FAILURE_MODE_MATRIX.md` 更新(additive)** — 新障害点 4 行を追加: {litellm_proxy_down, anthropic_unreachable(=proxy 経由で全承認モデル不達), agmsg_write_failure, result_missing} × {検知層, 止まり方(fail-closed 動作), blocked_reason/exit code, 運用対応(RUNBOOK 参照)}。
6. **`docs/RUNBOOK.md` 追記(1 節)** — llm_unavailable 発生時の確認手順(platform-health → LiteLLM Proxy 状態 → 再委譲)。タスクは open のまま止まり、自動再実行・自動降格しないことを明記。
