# P8-T02: LiteLLM Proxy 構成(承認モデル固定・ログ抑止・キー隔離)

- Author: orchestrator-fable5, 2026-07-08
- Basis: `.orchestration/analysis/litellm_claude_code_integration_review.md` 問題 1, 2, 7, 9 および §3.1。前提: `docs/INTEGRATION_BOUNDARY.md`(P8-T01 accepted)の Decisions。

## 1. Objective

LiteLLM Proxy を「基盤 Gateway の下流専用プロバイダアダプタ」として構成し、その不変条件(承認 Anthropic モデルのみ / 生プロンプト非保存 / キー隔離 / localhost bind)を機械検査するゲートを追加する。Proxy 自体の起動・ネットワーク接続は行わない(構成と検査のみ)。

## 2. Deliverables

1. **`config/litellm/config.yaml`(新規)** — レビュー文書 §3.1 を基に、以下の不変条件を満たす:
   - `model_list` は Anthropic モデルのみ(`anthropic/` プレフィクス必須)。エイリアスは `worker-fast`(claude-haiku-4-5)/ `worker-main`(claude-sonnet-4-6)/ `worker-heavy`(claude-opus-4-8)。※実在のモデル ID に合わせて `claude-haiku-4-5-20251001` 等の完全 ID を使ってよい。
   - fallbacks は同一 model_list 内のみ(worker-main→worker-fast)。`num_retries: 2` 上限。
   - `litellm_settings.turn_off_message_logging: true` 必須。success/failure callback は `platform_audit_forwarder`(メタデータのみ基盤台帳へ転送する規約名。実装は P8-T03 以降)。
   - `general_settings.master_key: os.environ/LITELLM_MASTER_KEY`。API キー参照は `os.environ/ANTHROPIC_API_KEY` のみ。他プロバイダのキー参照が一切ないこと。
   - bind は 127.0.0.1(config 内 `server_settings`/起動手順のどちらでも可だが、検査可能な形で config か docs に固定)。
2. **`scripts/check-litellm-config.mjs`(新規、依存追加なし)** — config.yaml を検査し、以下のいずれかの違反で exit 1: (a) `anthropic/` 以外の model 参照、(b) `turn_off_message_logging: true` の欠落、(c) `ANTHROPIC_API_KEY`/`LITELLM_MASTER_KEY` 以外の `os.environ/` キー参照、(d) fallback 先が model_list 外、(e) 127.0.0.1 以外への bind 指定。YAML の完全パーサは不要(行ベース/正規表現の決定論検査で可。制約をコメントで明記)。
3. **`litellm_config` ゲート追加** — `scripts/validate-release.mjs` に additive で組み込み、上記検査を実行。違反 config での失敗を負のテストとして検証ログに証明を残す(一時ファイルで違反 config を検査して exit 1 を確認)。
4. **`docs/LITELLM_PROXY.md`(新規)** — 運用規約: (a) 実行は基盤 Gateway と同ホストの分離環境(例: `uvx litellm --config config/litellm/config.yaml`。本リポジトリの依存には追加しない)。(b) 127.0.0.1 bind、基盤 Gateway 以外の到達は OS レベル遮断。(c) キー管理: ANTHROPIC_API_KEY は Proxy 環境のみが保持、エージェント・Flue・Gateway には LiteLLM 仮想キーのみ配布。(d) 仮想キーは Agent Profile 単位で発行し、許可モデル・予算上限・レート制限を設定。予算超過は fail closed(自動降格禁止)。(e) LiteLLM Proxy DB を使う場合はメッセージ本文が保存されないことをリリース検査対象とする(将来 MVP-SC-004 相当)。
5. **`.env.example` に追記** — `LITELLM_MASTER_KEY=`、`LITELLM_BASE_URL=http://127.0.0.1:4000`(プレースホルダのみ、実値禁止)。
6. **`docs/SECRETS_MANAGEMENT.md` に参照 1 行追記**(キー custody の節から LITELLM_PROXY.md へ)。

## 3. Constraints

- **依存追加禁止**(litellm を package.json/requirements.txt に追加しない)。**src/ 配下・policy/ 配下の変更禁止**(Gateway 接続は P8-T03)。ネットワーク・LLM 呼び出し禁止。push 禁止。
- validate-release への変更は additive なゲート追加のみ。既存ゲートを弱めない。
- 未コミットの既存 dirty ファイルに触れない・ステージしない。
- Commit prefix `P8-T02:`、author mryfmo <mryfmo@gmail.com>、署名分離フラグは従来どおり。

## 5. Acceptance criteria

1. `node scripts/check-litellm-config.mjs` が正 config で exit 0、違反 config(5 種それぞれ)で exit 1 — 検証ログに証跡。
2. `npm run validate-release` exit 0 かつ `litellm_config` ゲートが出力に現れる(ゲートは 23 個になる)。
3. config.yaml が §2.1 の不変条件をすべて満たす。他プロバイダ参照ゼロ。
4. Artifacts 5 点所定パス。
