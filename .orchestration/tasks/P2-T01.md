## 1. Role

You are Codex CLI, model gpt-5.5, reasoning effort high, standing agmsg worker codex-gpt55-high. Worker, not orchestrator. Perform only this task.

## 2. Objective

Make `npm ci` and the `opa` release gate work on both linux-x64 and darwin (arm64/x64) without `--force` and without external wrappers, by using per-platform optional dependencies and platform-aware binary resolution.

## 3. Defensive engineering scope

## 4. Background

- Verified facts (orchestrator, 2026-07-05):
  - `agent-control-specification-opa-linux-x64@0.3.1-beta.0` is a hard dependency with os=linux/cpu=x64 → plain `npm ci` fails EBADPLATFORM on darwin/arm64 (P0-T02).
  - `agent-control-specification-opa-darwin-arm64@0.3.1-beta.0` and `-darwin-x64@0.3.1-beta.0` exist on the public registry.
  - `src/lib/opa.ts` `opaBinary()` hardcodes the linux package path, overridable via `EAP_OPA_BINARY`.
  - Current darwin workaround: Homebrew OPA 1.18 + `~/.local/bin/opa-v0compat` wrapper (injects `--v0-compatible` because the policy files use Rego v0 syntax). If the darwin-arm64 npm package bundles a 0.x-era opa, the wrapper becomes unnecessary for repo workflows — verify and report which OPA version the bundled binaries are.
- Dependency: P1-T03b accepted (validate-release currently 17/17 with the wrapper).
